# Генерация проектной документации 1С: ТЗ, Сметы, Планы и Видео

---

## 1. Сборка ТЗ и отчетов в Word по ГОСТ 7.32 (`tools/docs/md2docx.py`)

Инструмент конвертирует Markdown-файл в красиво оформленный документ Word (`.docx`) со строгим соблюдением корпоративного стиля и ГОСТ 7.32-2017:
* Автоматический титульный лист с наименованием заказчика, исполнителя, даты и согласующих лиц.
* Таблица версий документа (история правок).
* Автонумерация таблиц, рисунков и приложений.
* Фирменные рамки предупреждений/примечаний, таблицы, блоки кода с подсветкой синтаксиса.

### Конфигурация сборки (`tools/docs/docs_config.json`):
```json
{
  "project": "Модернизация подсистемы обмена данными",
  "client": "ООО «Клиент»",
  "author": "Ширшов Д.А.",
  "documents": [
    "ТЗ_Обмен_EnterpriseData.md"
  ]
}
```

### Команда компиляции:
```powershell
python tools/docs/md2docx.py tools/docs/docs_config.json
```
Результат сохраняется в `tools/docs/DOCX/`.

## 2. Планы внедрения, сметы и диаграммы Ганта (`tools/plans/`)

Позволяет из единой модели задач сформировать полный пакет документов для договора:
* **Excel (`.xlsx`)**: Гант по неделям, реестр этапов, график платежей с формулами сумм.
* **Word (`.docx`)**: Печатный текстовый план с графиком для вставки в приложение к договору.
* **Mermaid (`.mmd`)**: Диаграмма Ганта для вставки в проектные записки.
* **HTML**: Интерактивная веб-версия для демонстрации клиенту на экране.

### Порядок работы:
1. Задать этапы, задачи, ставки и зависимости в `tools/plans/model.py`.
2. Запустить расчет модели:
   ```powershell
   cd "tools/plans"
   python model.py
   ```
   Скрипт проверяет арифметику (часы × ставка = ₽, отсутствие кассовых разрывов) и записывает `plan.json`.
3. Сгенерировать клиентские файлы:
   ```powershell
   python gen_xlsx.py           # Создает смету и Гант в Excel (out/*.xlsx)
   python gen_docx.py --html    # Создает Word-версию плана
   python gen.py --client       # Создает клиентский HTML
   ```

## 3. Извлечение скриншотов из видеозаписей встреч (`tools/video/video_frames.py`)

Когда заказчик продемонстрировал ошибку или процесс на видео созвона, инструмент позволяет быстро получить скриншоты для ТЗ или баг-репорта (требуется `ffmpeg`):

```powershell
# 1. Посмотреть длительность и свойства видео
python tools/video/video_frames.py probe "запись_созвона.mp4"

# 2. Создать контактный лист (обзор видео одной картинкой-сеткой)
python tools/video/video_frames.py sheet "запись_созвона.mp4" -o "обзор.png"

# 3. Вырезать точные кадры по секундам (с обрезкой плиток участников созвона)
python tools/video/video_frames.py grab "запись_созвона.mp4" --at 120,345,612 --crop 1070x566+232+165 -o "кадры"
```
Формат `--crop`: `ШИРИНАxВЫСОТА+X+Y` — срезает лишнее, оставляя только окно 1С.

## 4. Регламент подготовки чистовых документов для заказчика и руководства (.docx)

* **Только чистовое согласованное предложение:** Запрещено выносить во внешние документы внутренние разделы «Шпаргалка для защиты решения», таблицы отброшенных архитектурных альтернатив ADR и предположения. Вся внутренняя техническая предыстория остается в `ТЗ_Разработчика_<Номер>.md`.
* **«Человеческий» язык без англицизмов:** Строгий запрет на ADR, Guard, Guard Clause, Early Return и др. Использовать профессиональные русскоязычные термины: «упреждающий контроль», «проверка остатка», «уведомительный характер».
* **Запрет на артефакты агента/IDE:** Никаких путей к файлам исходников (`Documents/.../ObjectModule.bsl`), команд CLI (`oscript ...`, `lint_bsl_diff.py`). Использовать стандартные понятия платформы 1С: «модуль объекта документа», «общий модуль».
* **Оформление по стандарту (ГОСТ 7.32):** Times New Roman 12, межстрочный интервал 1.15, поля 20 мм, титульный лист, графические скриншоты, таблицы параметров и регламентов.
