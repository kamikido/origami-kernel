# Обмены 1С: «Конвертация данных» 2.0 — правила и обработка выгрузки

Отработано на обменах ЗУП 3.1 → УПП 1.3, УТ 11 → БП 3.0 (платформы 8.3.27 и 8.5.1).

---

## 1. Ловушка «В данной транзакции уже происходили ошибки!»

* **Симптом:** При попытке загрузки XML-файла правил обмена платформа выдаёт ошибку `В данной транзакции уже происходили ошибки!`. Место падения указывает на поиск значения-приемника в совершенно исправном правиле.
* **Причина:** У одного из правил конвертации объектов (ПКО) **отсутствует тег источника**.
  * Загрузчик получает пустую ссылку на объект-источник. Если у правила остались строки соответствия значений с заполненным источником, он пытается записать элемент подчинённого справочника с пустым владельцем.
  * Платформа перехватывает исключение внутри, но транзакция базы уже помечена как поврежденная — падает следующее обращение к базе данных!
* **Что делать:**
  1. Не доверять месту падения. Разобрать XML правил и найти все теги `<Правило>` без атрибута источника, у которых внутри есть свойства с непустым источником.
  2. Если приёмник — ссылочный тип, а источник передаётся строкой, у правила конвертации должен быть явно указан источник примитивного типа `Строка`, а не отсутствующий тег.
  3. Проверить XML на дубли кодов правил конвертации.

## 2. Скорость выгрузки: рекурсивный обход подсистем БСП

* **Симптом:** Выгрузка небольшого документа (200 строк) занимает более минуты при быстрых запросах к БД.
* **Причина:** Перед каждым вызовом `Выполнить(<обработчик>)` механизм обмена проверяет текст на запрещенные методы через вызов БСП `ПодсистемаСуществует` → `ИменаПодсистем()`. Это полный рекурсивный обход дерева подсистем без кэширования (~900 итераций на вызов).
  * 12 обработчиков свойств ТЧ × 200 строк = 2400 проверок, что даёт более 2 миллионов бессмысленных итераций и забирает до 80% времени выгрузки!
* **Оптимизация:**
  1. Обработчики свойств вида `Значение = ОбъектКоллекции.Реквизит;` заменить прямым указанием источника в ПКС (`<Источник Имя="Реквизит" />`).
  2. Глобальный обработчик «Перед конвертацией объекта» (срабатывающий на каждый зависимый справочник по ссылке) перенести в «Перед выгрузкой объекта», если он фильтрует только документы.
  3. Удалить обработчики, в которых остался только закомментированный код: платформа считает обработчик непустым, если в нём есть хоть один символ комментария.

## 3. Правку правил «не видно»: правила внутри макета EPF

* **Симптом:** Файл правил на диске исправлен, но обработка выгрузки продолжает работать по старой логике.
* **Причина:** Внешняя обработка обмена читает правила не из внешнего файла, а из собственного двоичного макета (`ПолучитьМакет` → временный файл).
* **Что делать:**
  * Разобрать `.epf` на исходники (`vrunner epf decompile`).
  * Заменить `Templates/<ИмяМакета>/Ext/Template.bin` актуальным файлом правил.
  * Собрать `.epf` обратно (`vrunner epf compile`). Разборку и сборку выполнять строго в базе с целевой конфигурацией, чтобы не потерять общие картинки и ссылочные типы.
