# Расширения конфигурации 1С: архитектура, грабли и XML

Проверено на боевых базах УТ 11.5, БП 3.0, WMS (платформы 8.3.13, 8.3.27, 8.5.1).
Симптомы большинства ошибок ниже являются «молчаливыми»: конфигуратор и синтаксический контроль чисты, но в режиме предприятия форма не открывается, элементы пропадают или падают с непонятными исключениями.

---

## 1. Заимствованная форма без блока `<BaseForm>` не применяется

В `Ext/Form.xml` заимствованной формы расширения обязан быть блок:
`<BaseForm version="2.x">…</BaseForm>` — **полная копия исходной типовой формы** (содержимое корневого `<Form>` без обёртки). Платформа накладывает изменения формы по дельте между ней и `<BaseForm>`.

* **Симптом отсутствия `BaseForm`:** Платформа накладывает модуль формы, но **НЕ накладывает изменения элементов**. Код падает на собственных элементах:
  * `Поле объекта не обнаружено (<имя элемента>)` — при обращении `Элементы.<имя>`.
  * `Переменная не определена (<имя реквизита>)` — при чтении реквизита формы.
  * Присваивание реквизиту ошибки не дает (создается локальная переменная), падение происходит в месте первого чтения!
* **Как проверить:** У корректной заимствованной формы размер файла XML примерно вдвое больше типового (форма + BaseForm).
* **При генерации формы скриптом:** Блок `BaseForm` дописывать самым последним шагом, уже после всех `replace` в тексте формы.

## 2. Роли и права на объекты и реквизиты расширения

Типовая роль «ПолныеПрава» конфигурации **НЕ даёт прав** на объекты расширения (даже администратору), несмотря на признак «Устанавливать права для новых объектов».

* **Реквизиты, добавленные в типовой объект:** Самый коварный случай!
  * Если нет прав на добавленный реквизит, платформа **молча убирает элемент с формы**.
  * Код расширения падает с ошибкой: `Поле объекта не обнаружено (<элемент>)` — легко спутать с конфликтом наложения форм.
  * Форма может выдать: `Поле объекта недоступно для чтения (<реквизит>)`.
* **Правило:**
  1. На каждый новый объект или добавленный реквизит — своя роль в расширении с правами `View`, `Edit`.
  2. В базах с БСП 3.1 роли расширения раздавать через **профили групп доступа**, а не напрямую пользователю ИБ (прямое назначение затирается регламентной синхронизацией пользователей БСП).
  3. Для внешних HTTP-сервисов в расширении без явной роли возвращается `403 Недостаточно прав для использования ресурса`.

## 3. Функциональные опции: физическое удаление с формы

Если элемент формы привязан к реквизиту, входящему в функциональную опцию:
* При выключенной опции платформа **физически удаляет элемент из коллекции `Элементы`**, а не делает `Видимость = Ложь`.
* Код вида `Элементы.Организация.Видимость = Истина;` падает с `Поле объекта не обнаружено (Организация)`.
* **Правило:** Перед программным обращением к элементам, зависящим от ФО, проверять `ПолучитьФункциональнуюОпцию(...)` либо проверять наличие элемента: `Если Элементы.Найти("Имя") <> Неопределено Тогда`.

## 4. Безопасный режим и защита от опасных действий

* По умолчанию расширения подключаются в безопасном режиме. В нём запрещены: внешние компоненты, прямой вызов команд ОС, работа с файловой системой за пределами разрешенных каталогов, привилегированный режим.
* При загрузке через `vrunner cfe load` параметры безопасности могут сбрасываться или требовать ключей `--safe-mode` / `--unsafe-action-protection`.
* При интерактивной отладке в справочнике `Расширения` снимать флажки «Безопасный режим» и «Защита от опасных действий».

## 5. Расширение как XML-код (Разработка без конфигуратора)

Методика создания и сборки расширений из исходных XML-файлов:

1. **Детерминированные UUID:**
   * Генерировать строго через `uuid.uuid5(namespace, "Вид|Имя")`. Случайные UUID при каждой пересборке ломают обновление ИБ и приводят к потере данных таблиц расширения.
2. **Три идентификатора заимствованного объекта:**
   * Собственный `uuid` объекта — свой (детерминированный). Использование uuid типового объекта вызывает `Конфликт внутренних идентификаторов у объекта`.
   * Ссылка на типовой объект (`ExtendedConfigurationObject`) — необязательна, платформа сопоставляет по имени.
   * Порожденные типы (`InternalInfo/GeneratedType`): состав брать из выгрузки целевой конфигурации, но идентификаторы `TypeId`/`ValueId` генерировать свои детерминированные.
3. **Заглушки дочерних объектов (`Adopted`):**
   * Все заимствованные реквизиты и табличные части, к которым обращается заимствованная форма, обязаны присутствовать в XML объекта как заглушки `<ObjectBelonging>Adopted</ObjectBelonging>`, иначе путь к данным формы не разрешается.
4. **Опасность `xml.etree.ElementTree` в Python:**
   * Стандартный модуль `xml.etree` теряет префиксы пространств имен (например, `style:SpecialTextColor` превращается в ошибку `Ссылка на неизвестный цвет style:SpecialTextColor`). Для модификации форм использовать текстовые замены или специализированный генератор `tools/1c/formgen.py`.
5. **Идентификаторы добавленных элементов формы:**
   * Номера добавленных элементов начинать с заведомо свободного диапазона (5000+), а реквизитов и команд — с 1 000 000, чтобы избежать пересечений с типовыми идентификаторами.

## 6. Контроль перехватов перед обновлением конфигурации

Перед накатом типового релиза на базу с расширениями:
* Проверить все методы с директивой `&Вместо`. По возможности переводить на `&ИзменениеИКонтроль`, `&Перед` или `&После`.
* В `&Вместо` всегда вызывать `ПродолжитьВызов(...)`, кроме случаев осознанного полного вытеснения логики.
* Проверять сигнатуры измененных типовых процедур: добавление разработчиками 1С нового обязательного параметра в типовой метод ломает вызов перехваченного метода в расширении.

## 7. Обработчики системных событий формы в расширении

* **Директивы `&Перед` / `&После` для событий формы не существуют:**
  Стандартные события формы (`OnCreateAtServer`, `OnOpen`, `BeforeWrite` и др.) перехватываются **только через коллекцию событий формы в XML**:
  ```xml
  <Events>
      <Event name="OnCreateAtServer" callType="After">САА_ПриСозданииНаСервереПосле</Event>
  </Events>
  ```
* **Директива компиляции в BSL:**
  В модуле формы процедура-обработчик объявляется со стандартной директивой контекста (`&НаСервере`, `&НаКлиенте`), а НЕ аннотацией перехвата:
  ```bsl
  &НаСервере
  Процедура САА_ПриСозданииНаСервереПосле(Отказ, СтандартнаяОбработка)
      // Логика расширения
  КонецПроцедуры
  ```
  Использование `&После("ПриСозданииНаСервере")` является синтаксической ошибкой: директивы перехвата предназначены исключительно для процедур и функций модулей, а не событий формы.

## 8. Минималистичный XML заимствованной формы при программной доработке

* **Ошибка «Неверный путь к данным»:**
  Если в `Ext/Form.xml` заимствованной формы расширения скопировать базовые динамические списки или таблицы (например, привязанные к регистрам сведений базовой конфигурации), консольный валидатор `ibcmd` при сборке CFE падает с блокирующей ошибкой `Неверный путь к данным`, требуя заимствования всех связанных объектов базы.
* **Правило:**
  При программном добавлении реквизитов и элементов (через `ПриСозданииНаСервере` / `ИзменитьРеквизиты`) в XML формы расширения переносить **только целевые группы-контейнеры** (куда программно встраиваются элементы) и объявление события в `<Events>`. Все неиспользуемые динамические списки и таблицы удалять (утилита `tools/1c/clean_form_xml.py`).
