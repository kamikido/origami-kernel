# Код, метаданные, расширения

Часть свода стандартов 1С. Сгенерировано сервером «Стандарты» — не редактировать.
Соседние темы — в таблице SKILL.md, детали по любой из них — инструмент search_knowledge.

- Пиши тексты модулей на русском языке. Исключение — веб-сервисы (имена методов и параметров можно на английском) и идентификаторы внешних информационных систем.
- Используй букву «ё» в текстах модулей и в интерфейсных текстах для пользователя.
- Используй только штатные и документированные возможности платформы — никаких недокументированных приёмов и трюков.
- Не оставляй в конфигурации ошибок, обнаруживаемых проверкой конфигурации — кроме отдельных обоснованных исключений (несущественные предупреждения, подключаемые из кода обработчики формы и т.п.).
- Не дублируй код копированием — в копию переносятся все ошибки оригинала, а при правке легко пропустить часть вхождений; повторно используемые алгоритмы выноси в общие модули.
- Образуй имена от терминов предметной области — имя должно быть «говорящим» и пояснять назначение без дополнительного описания.
- Имя процедуры образуй от неопределённой формы глагола (ЗагрузитьКонтрагента, не ЗагрузкаКонтрагента).
- Имя функции образуй от описания возвращаемого значения (ПолноеИмяПользователя, не ПолучитьПолноеИмяПользователя).
- **Все отступы в текстах модулей (BSL) и в XML-файлах форм и метаданных делай символами табуляции, а не пробелами.** Табуляция — родной формат выгрузки Конфигуратора; пробелы вместо табов ломают единообразие и порождают ложные расхождения при сравнении/загрузке. Один уровень вложенности — один символ табуляции. При правке существующего файла сохраняй его табуляцию: не заменяй ведущие табы на пробелы и наоборот. Инструменты точечной замены по образцу строки не найдут фрагмент, если отступ в образце набран пробелами, а в файле — табами. Если не уверен в числе табов — перечитай точный фрагмент или правь программно, вычисляя базовый отступ из самого файла.
- **Идентичность типа заимствованной заглушки бери ТОЛЬКО из той базы, куда разворачивается расширение, — никогда из стороннего дампа.** Заимствуя объект конфигурации в расширение (справочник, документ и т.п. — файл-заглушка ObjectBelonging=Adopted с блоком InternalInfo), не копируй блок InternalInfo/GeneratedType (TypeId+ValueId для Object/Ref/Selection/List/Manager) из дампа ДРУГОЙ базы или другого экземпляра конфигурации. У каждого объекта — своя идентичность типа, и целевая база узнаёт только идентичности из СВОЕЙ родословной. Совпадения имён и uuid объектов (ExtendedConfigurationObject) НЕДОСТАТОЧНО: TypeId у одноимённых объектов в разных базах расходится (особенно если объект в базе пересоздавали). Если CatalogRef.X.TypeId заглушки ≠ базовому, то ссылка cfg:CatalogRef.X при работе МОЛЧА не разрешается в реальный тип → поле-ссылка деградирует в ввод строки (не выбирается из справочника), а Ссылка.ПолучитьОбъект() падает с «Значение не является значением объектного типа». Ни CheckConfig, ни просмотр исходников этого не ловят — в исходниках тип виден как читаемое имя cfg:CatalogRef.X, повисших/пустых TypeId нет, проверка конфигурации зелёная. Верный источник заглушки: заимствование Конфигуратором САМОЙ целевой базы, либо дамп её базовой конфигурации (DumpConfigToFiles без -Extension из этой же базы).
- **После заимствования и применения сверяй идентичность заглушки с базой.** Обязательный контроль после заимствования объекта конфигурации в расширение через загрузку из файлов (файл-заглушка ObjectBelonging=Adopted): выгрузи базовую конфигурацию целевой базы (DumpConfigToFiles без -Extension) и сравни у каждого заимствованного объекта <GeneratedType name="CatalogRef.<Имя>">/<TypeId> заглушки с базовым. Расходится хоть один — идентичность чужая, заглушку надо пересобрать из базы (сохранив свой <Catalog uuid>, ObjectBelonging=Adopted, ExtendedConfigurationObject, ChildObjects с добавленными реквизитами). Не полагайся на зелёный CheckConfig как на признак корректности заимствования.
- Ставь Попытка-Исключение локально на конкретный проблемный вызов — не оборачивай большие блоки кода, чтобы не перехватить чужие, несвязанные ошибки.
- Никогда не перехватывай исключение «вслепую» пустым блоком — обязательно записывай событие в журнал регистрации, иначе проблему потом невозможно диагностировать.
