# Формы, интерфейс, клиент-серверное взаимодействие

Часть свода стандартов 1С. Сгенерировано сервером «Стандарты» — не редактировать.
Соседние темы — в таблице SKILL.md, детали по любой из них — инструмент search_knowledge.

- Выполнение локальной или глобальной команды формы должно приводить не более чем к одному серверному вызову — данные для чисто клиентских команд (открытие формы, установка отбора, проверка «ЭтоГруппа») готовь заранее в «ПриСозданииНаСервере» и клади в реквизиты формы.
- Не передавай на сервер больше данных, чем нужно для задачи: если серверной процедуре требуется одно значение, не делай вызов контекстным — выноси такую логику в функцию с директивой «НаСервереБезКонтекста», передавая ей только нужный параметр.
- Открывай формы методом глобального контекста «ОткрытьФорму», а не связкой «ПолучитьФорму» с последующим открытием — это разделяет интерфейс работы с формой и детали её реализации, гарантирует инициализацию формы в обработчике «ПриСозданииНаСервере» и держит весь код инициализации в одном месте.
- Минимизируй объём кода, выполняемого на клиенте: сложные ресурсоёмкие алгоритмы размещай в серверном коде и обращайся к ним с клиента минимально необходимое число раз — клиентский компьютер обычно слабее сервера, а в веб-клиенте интерпретатор встроенного языка работает заметно медленнее.
- Для вывода любых сообщений пользователю используй объект «СообщениеПользователю», даже когда сообщение не привязано к элементу управления формы, а метод «Сообщить» не применяй — при наличии БСП используй процедуру «СообщитьПользователю» общих модулей «ОбщегоНазначения» или «ОбщегоНазначенияКлиент», работающую через «СообщениеПользователю».
- Не управляй из кода элементами формы, которые автоматически формируются платформой — в ряде сценариев платформа пересоздаёт такие элементы (например, командная панель списка перезаполняется после изменения свойства «ОсновнаяТаблица» динамического списка), и программно установленные свойства теряются; при необходимости устанавливай их повторно.
- Серверные вызовы из клиентского кода, которые в обычных сценариях могут выполняться дольше 8 секунд (формирование отчёта, групповая обработка, загрузка или выгрузка данных, заполнение больших табличных частей), выполняй асинхронно фоновым заданием, а не синхронным вызовом — иначе браузер или веб-сервер прервут операцию (ошибка 504), а пользователь не сможет её отменить.
- В конфигурациях для веб-клиента (платформа 8.3 и выше) не используй модальные формы и диалоги: свойство конфигурации «Режим использования модальности» установи в «Не использовать» и вместо модальных методов вызывай их немодальные аналоги с блокированием окна владельца или всего интерфейса — модальные окна не входят в стандарт веб-разработки и не работают в ряде браузеров.
- **Поле периода на форме делай в стандартном виде «Период: [дата] — [дата] […]»: один реквизит типа «СтандартныйПериод», два поля дат через декорацию-тире и обычная кнопка-картинка выбора; диалог открывай немодально; настройку сохраняй штатно.** Не заводи два отдельных реквизита-даты; не оформляй кнопку выбора как кнопку командной панели (CommandBarButton) внутри обычной группы — она рендерится не как «…» и весь блок периода выглядит криво; не вызывай модальные диалоги (в веб-клиенте запрещены); не восстанавливай сохранённый период вручную. Эталон раскладки — обработка «Исправление счетов учёта товаров в документах в БП 3», Sources\Processor\Forms\Форма\Ext\Form.xml. Как именно: (1) модель данных — ОДИН реквизит формы типа СтандартныйПериод (v8:StandardPeriod) со свойством «Сохраняемые данные» (SavedData=true) и включённым автосохранением настроек формы (АвтоматическоеСохранениеДанныхВНастройках = Использовать) — период сохраняется между сеансами и корректно восстанавливается; (2) раскладка (именно она даёт правильный внешний вид) — горизонтальная группа без собственного заголовка (ShowTitle=false), внутри по порядку: поле ввода с ПутьКДанным = <Реквизит>.ДатаНачала, заголовок «Период» (или «Период статистики»), РасположениеЗаголовка = Лево; декорация-надпись (LabelDecoration) с заголовком «—» (тире) — визуальный разделитель между датами; поле ввода с ПутьКДанным = <Реквизит>.ДатаОкончания, РасположениеЗаголовка = Нет; кнопка «…» — именно ОБЫЧНАЯ кнопка (Тип = UsualButton) с Отображение = Картинка и картинкой StdPicture.InputFieldSelect; (3) порядок свойств в XML формы (иначе загрузка из файлов ругается): у поля ввода — DataPath, Title, TitleLocation, Width, Wrap, ContextMenu, ExtendedTooltip; у группы с заголовком — Title, Group, Behavior, Representation, ShowTitle, ExtendedTooltip, ChildItems; id новых элементов (декорация, кнопка) бери заведомо выше максимального в форме; (4) поведение кнопки (на клиенте, немодально — для веб-клиента обязательно): команда открывает выбор стандартного периода без модальности — либо объект платформы (есть всегда) ДиалогРедактированияСтандартногоПериода: Диалог = Новый ДиалогРедактированияСтандартногоПериода; Диалог.Период = <Реквизит>; Диалог.Показать(Новый ОписаниеОповещения(…)), результат — СтандартныйПериод; либо общая форма БСП/типовой — ОткрытьФорму("ОбщаяФорма.ВыборСтандартногоПериода", …) с оповещением, результат — структура НачалоПериода/КонецПериода; (5) в обработчике завершения: если результат = Неопределено — выход (пользователь отменил), иначе перенеси в реквизит ДатаНачала/ДатаОкончания и Вариант (или НачалоПериода/КонецПериода); (6) умолчания периода задавай только в ПриСозданииНаСервере и только если период пуст (Не ЗначениеЗаполнено(<Реквизит>.ДатаНачала)) — платформа восстанавливает сохранённые настройки ПОСЛЕ этого обработчика и перекроет умолчания.
- По умолчанию вызывай серверные процедуры модуля формы внеконтекстно (директива «&НаСервереБезКонтекста»), передавая минимально необходимый объём данных — контекстный вызов дополнительно инициализирует методы и серверную копию данных формы, увеличивая время обработки.
