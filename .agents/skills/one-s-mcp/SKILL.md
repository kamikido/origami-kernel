# Работа с 1С через one-s-mcp

Сгенерировано приложением one-s-mcp — не редактировать вручную (перезапишется).

## Активная конфигурация

- **1С:Предприятие** (определяется активной базой в MCP)
- платформа 8.3.27 · БСП 3.1
- Выгрузка XML определяется файлом конфигурации проекта

Выяснять эти факты инструментами не нужно. Это сведения о базе, активной в момент, когда ты открыл скилл: если ответы инструментов пошли по другой базе — пользователь сменил активную базу в приложении, открой скилл заново.
Всё остальное о конфигурации (объекты, реквизиты, методы, формы) — только через приложение.

## Главное
- Сведения о конфигурации (объекты, реквизиты, методы, формы) бери ТОЛЬКО из приложения, не
  выдумывай. Сначала разведай реальную конфигурацию инструментами ниже.
- Перед тем как писать код/запрос или менять метаданные — подбери правила под задачу у службы
  стандартов (`1c-standards`) и следуй им: свод правил платформы и перечень подсистем БСП —
  там, без них ответ будет неверным.
- Сложную составную задачу («сделай обработку/отчёт», «проанализируй влияние изменения») отдавай
  агенту — он сам сходит к нужным службам.

## Каталог инструментов: что для чего
| Нужно | Чем |
|---|---|
| Найти код/объект по смыслу или точному имени | поиск по конфигурации |
| Понять связи, влияние изменения, цепочку вызовов | граф конфигурации |
| Найти готовый приём или функцию БСП | справочник БСП |
| Сверить поведение/синтаксис платформы | справка платформы |
| Сделать или поправить форму | сервер форм |
| Проверить синтаксис и стиль BSL после правок | проверка синтаксиса |
| Подобрать правило/стандарт под задачу | поиск по стандартам |
| Составная задача целиком | агент |

Точные имена инструментов зависят от того, что открыто в этой сессии: часть служб может быть за
агентом, часть — напрямую. Если служба не видна среди инструментов сессии — её сейчас нет, не выдумывай
вызов.

## Дисциплина «сначала приложение»
1. Для любого поиска по конфигурации (код, объекты, использования, цепочки вызовов, формы, структура)
   сперва используй индекс приложения (поиск/граф). Обычный текстовый поиск по файлам (Grep/Glob) —
   крайнее средство.
2. Уходишь в текстовый поиск — коротко напиши в ответе, что уже пробовал через приложение и почему не
   хватило. Молчаливый откат к текстовому поиску — дефект.
3. Пусто с первого раза — переформулируй запрос (шире/уже, другой режим поиска), а не повторяй тот же
   запрос и не бросайся сразу к текстовому поиску.
4. Не повторяй один и тот же вызов с теми же параметрами по неизменному состоянию.
5. Текстовый поиск законен без попытки приложения только для не-1С файлов (markdown, json/yaml,
   логи) или файла, уже прочитанного в этой сессии.
6. Модуль читай фрагментом, а не файлом: сперва состав процедур модуля, затем сигнатура нужной,
   и только потом её тело. Модули 1С бывают на десятки тысяч строк — чтение файлом целиком
   вытесняет из контекста саму задачу. Файл целиком законен, когда ты его сейчас правишь, когда
   сам только что его изменил или когда в индексе нужного фрагмента не нашлось.

## Служба не ответила
Инструмент приложения молчит, оборвался по времени или вернул ошибку выполнения — это НЕ повод
перейти на чтение выгрузки файлами. Порядок: один повтор вызова, и если снова сбой — остановись
и скажи пользователю, какая служба не отвечает и что проверить (открыто ли приложение, не идёт
ли индексация, выбрана ли активная конфигурация). Обход сбоя текстовым поиском по выгрузке даёт
ответ по неполной картине и вычерпывает контекст целыми модулями: молчание службы означает, что
индекс сейчас недоступен, а не что искать надо руками.
Если пользователь только что сменил активную базу в приложении, службы несколько секунд
перезапускаются — подожди и повтори вызов.

Не путать со случаем, когда инструмент ОТВЕТИЛ инструкцией для пользователя
(«установите/проиндексируйте в приложении») — это не сбой, порядок для него ниже.

## Настройки и параметры: фолбэки вместо допроса
Работа не начинается с вопросов про окружение и не блокируется на настройках. Незаданный параметр —
это не вопрос пользователю и не повод угадывать: действуй по колонке «Если не задано». Вопросы по
сути задачи (бизнес-требования) этим не ограничены — правило только про окружение и параметры
инструментов.

| Параметр | Класс | Если не задано |
|---|---|---|
| Версия платформы/БСП в инструментах справки | умолчание | не передавай — возьмётся из настроек приложения |
| Фильтр extension/source в поиске и графе | умолчание | не передавай — работаешь по всей итоговой конфигурации |
| Охват (scope) в поиске по стандартам | умолчание | не передавай — активная конфигурация |
| Какое сравнение брать (служба сравнений) | фолбэк молча | выбери по смыслу задачи из списка сравнений |
| Префикс имён новых объектов/реквизитов | фолбэк молча | сними с существующих доработок конфигурации; образца нет — без префикса |
| Маркеры доработок в коде (автор, № задачи) | фолбэк молча | как в образцах рядом; образца нет — не ставь |
| Подсистема размещения нового объекта | фолбэк молча | по образцу похожих объектов |
| Основная конфигурация или расширение — куда класть новые объекты и доработки существующих | спросить в момент операции | сперва выведи из задачи и практики конфигурации (список расширений, где лежат существующие доработки); не выводится — один вопрос прямо перед изменением метаданных |

Классы:
- «умолчание» и «фолбэк молча» — спрашивать пользователя про такой параметр запрещено; пустое
  значение само по себе валидно.
- «спросить в момент операции» — один вопрос, и только когда операция реально дошла до этого
  параметра; не на старте задачи и не «впрок для полноты».

Если инструмент вернул инструкцию для пользователя («установите/проиндексируйте в приложении») —
это и есть нужный момент: передай её пользователю и продолжай остальные части задачи, не
останавливай работу целиком.
