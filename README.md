# Origami Kernel v1.1

> **Origami** — открытый архитектурный фреймворк и инструментарий автономной разработки для платформы 1С:Предприятие 8.3 / 8.5.
> Философия Origami: единый чистый лист базового ядра, из которого путем добавления модулей знаний (Playbooks) складывается любая сложная архитектурная фигура корпоративного уровня.

Origami предоставляет стандартизированную операционную среду, объединяющую инженера и интеллектуальных агентов в надежный конвейер: от консилиума моделей (Pre-Modeling Council) и непрерывного обучения на реальных совещаниях (`origami feedback`) до статического анализа BSL в режиме Pure-Diff и автоматизированной сборки.

---

## 1. Архитектурная модель Upstream / Downstream

Фреймворк построен по модульному принципу: централизованное неизменяемое ядро (Upstream Core) и изолированные проектные слои (Project Overlays).

```
                ┌──────────────────────────────────────────────┐
                │          Origami Kernel (Upstream)           │
                │     https://github.com/kamikido/origami-kernel│
                └──────────────────────┬───────────────────────┘
                                       │
              ┌────────────────────────┼────────────────────────┐
              │ python tools/deploy.py update                   │
              ▼                        ▼                        ▼
┌──────────────────────────┐ ┌───────────────────┐ ┌──────────────────────┐
│        Project A         │ │     Project B     │ │      Project C       │
│  (УТ 11 / Расширение 1)  │ │ (ERP / Модуль 2)  │ │  (БП 3 / Интеграция) │
└──────────────────────────┘ └───────────────────┘ └──────────────────────┘
```

### Принципы архитектурной изоляции:
1. **Безопасная односторонняя доставка:** Ядро обновляет общие инструменты, хуки и линтеры, гарантируя неприкосновенность файлов конкретного проекта (`origami.config.json`, `autumn-properties.json`, проектных правил `.agents/rules/`, тестов и метаданных конфигурации).
2. **Обезличенность и безопасность:** Ядро не содержит конфиденциальных данных, учетных записей, параметров авторизации и специфической бизнес-логики.
3. **Автономное развертывание:** Инициализация окружения в новом или существующем проекте выполняется единой командой `origami deploy init`.

## 2. Ключевые возможности

* **Когнитивная архитектура (Двухуровневая память):** Разделение кратковременной памяти правил ($\le 10\,000$ токенов) и долговременной памяти открытых плейбуков (`knowledge/playbooks/*.md`, 0 токенов в промпте).
* **Непрерывный цикл обучения (`origami feedback`):** Автоматическое извлечение архитектурных стандартов и слепых зон из реальных совещаний и генерация универсальных плейбуков.
* **Менеджер плейбуков (`origami playbook`):** Быстрый полнотекстовый поиск и чтение стандартов по темам (учет ущерба, факсимиле, интеграции, фоновые задания).
* **Многоуровневая отказоустойчивость (L1 / L2 / L3):** Автоматическая адаптация функционала под рабочее окружение (от базового Python до полноценного контура с COM-соединением и Vanessa-Automation).
* **Pure-Diff BSL Линтер:** Контроль стандартов разработки 1С строго на измененных строках (Green Hunks), исключающий блокировку релизов из-за чужого легаси-кода.
* **Архитектурный консилиум (Pre-Modeling Council):** Предварительный анализ бизнес-инвариантов, транзакционных блокировок, RLS и контекста исполнения через внешние LLM-сервисы.
* **Независимый аудит изменений (Adversarial Review):** Автоматизированная верификация диффов независимой моделью-критиком перед фиксацией изменений.
* **Универсальная интеграция с LLM:** Поддержка любого OpenAI-совместимого API (OmniRoute, LM Studio, Ollama, OpenRouter, DeepSeek, OpenAI).
* **Автоформатирование OneScript:** Приведение модулей к стандарту длины строки $\le 120$ символов с детерминированным переносом сложных выражений.

## 3. Когнитивная архитектура: Двухуровневая память

Чтобы предотвратить деградацию системного контекста в IDE (где лимит на правила составляет 20 000 токенов), Origami реализует принцип человеческого мозга:

```
┌────────────────────────────────────────────────────────────────────────┐
│               КРАТКОВРЕМЕННАЯ ПАМЯТЬ (System Prompt / Rules)           │
│   • Размер: ~10 000 токенов (константа, запас 50% до лимита IDE)       │
│   • Содержит только БАЗОВЫЕ РЕФЛЕКСЫ Senior 1C:                        │
│     - Не писать код без premodel и утвержденного ТЗ                    │
│     - Register-First: остатки только через регистр накопления          │
│     - Pure-Diff: строка <= 120, запрет ИЛИ в ГДЕ, метки // { + ... }   │
│     - Индекс тем: ссылки на плейбуки долговременной памяти             │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
               Точечный запрос по теме (read_file / origami playbook)
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│           ДОЛГОВРЕМЕННАЯ ПАМЯТЬ (knowledge/playbooks/*.md)             │
│   • Неограниченный объем знаний на диске                               │
│   • Расход токенов в системном промпте = 0!                            │
│   • Отчуждаемость: команды могут делиться файлами плейбуков            │
│     между проектами без изменения базовых правил                       │
└────────────────────────────────────────────────────────────────────────┘
```

## 4. Матрица уровней окружения (Graceful Degradation)

Origami автоматически диагностирует установленные компоненты и активирует соответствующий профиль возможностей:

| Уровень | Требования к окружению | Доступный функционал | Статус сдачи задач |
| :--- | :--- | :--- | :--- |
| **L1: Core** | Python 3.10+ и PowerShell 5.1+ | Pure-Diff BSL линтинг, предварительное моделирование, IDE-хуки | `[STATIC DRAFT]` |
| **L2: DevTools** | + OneScript 2.2+ и Git | Автоформатирование кода (`format_bsl.os --diff`), AST-анализ | `[CODE READY]` |
| **L3: Enterprise** | + Платформа 1С:Предприятие 8.3.27+ | COM-запросы к данным, сценарные тесты Vanessa, сборка CFE/EPF | `[VERIFIED]` |

## 4. Быстрый старт

### 1. Клонирование репозитория
```bash
git clone https://github.com/kamikido/origami-kernel.git
cd origami-kernel
```

### 2. Диагностика окружения
```powershell
.\tools\origami.ps1 doctor
```

### 3. Настройка LLM-провайдера (Опционально)
Origami поддерживает любые локальные и облачные OpenAI-совместимые эндпоинты:
* **Локальные модели (LM Studio / Ollama):** укажите переменную среды `OPENAI_BASE_URL` (например, `http://localhost:1234/v1`).
  > [!IMPORTANT]
  > **Особенности использования локальных моделей (Ollama / LM Studio):**
  > 1. Задайте размер контекста не менее 16 384 токенов (`num_ctx: 16384` в Modelfile или настройках). Контекст по умолчанию (4 096 токенов) обрезает большие git diff.
  > 2. Для reasoning-моделей (Qwen, DeepSeek-R1) установите лимит ответа не менее 4 096 токенов, чтобы цепочка рассуждений не обрывала результирующий JSON.
* **Облачные провайдеры:** задайте ключ доступа в переменной окружения:
  ```powershell
  $env:ORIGAMI_LLM_KEY = "sk-..."
  # Поддерживаются также стандартные переменные: OPENAI_API_KEY, OPENROUTER_API_KEY, DEEPSEEK_API_KEY
  ```
  *(Подробнее см. [.env.example](.env.example))*.

### 4. Развертывание в проект
```powershell
.\tools\origami.ps1 deploy init --target "C:\Projects\MyProject" --name "MyProject" --prefix "ext_" --extension "Customization" --infobase "C:\1C\Bases\my_project"
```

## 6. Консоль управления (Origami CLI)

Все операции выполняются через единый фасад `.\tools\origami.ps1`:

| Команда | Описание |
| :--- | :--- |
| `origami doctor` | Диагностика компонентов и определение уровня окружения (L1–L3) |
| `origami status` | Вывод информации о текущей конфигурации проекта |
| `origami config [show/get]` | Просмотр параметров `origami.config.json` |
| `origami lint-kernel` | Статический аудит стандартов ядра (OPCES-1.1, Zero-Leak, BOM) |
| `origami premodel "<задача>"` | Запуск консилиума моделей OmniRoute: цели, слепые зоны, риски |
| `origami feedback -m <файл>` | Извлечение архитектурных стандартов из совещания (Learning Loop) |
| `origami playbook [list/find]` | Каталог и полнотекстовый поиск стандартов долговременной памяти |
| `origami format <файл> [--diff]`| Форматирование BSL по стандарту 120 символов (OneScript) |
| `origami lint <файл> [опции]` | Pure-Diff статический анализ (`--git-diff`, `--tab-width 4`) |
| `origami audit <файл/diff>` | Независимый аудит качества кода моделью-критиком |
| `origami check <файл>` | Комплексный контроль качества (форматирование + линтинг) |
| `origami deploy status` | Аудит соответствия подчиненных проектов эталонному ядру |
| `origami deploy update` | Доставка обновлений ядра в проекты |
| `origami deploy init` | Развертывание платформенного контура в новый проект |

## 7. Структура репозитория

- `tools/` — платформенный инструментарий (раннер `origami.ps1`, `doctor.py`, `premodel.py`, `feedback.py`, `playbook.py`, линтинг BSL и аудит ядра).
- `docs/standards/` — официальные нормативные стандарты платформы ([OPCES-1.1](docs/standards/origami-engineering-standard.md)).
- `knowledge/playbooks/` — долговременная память архитектурных стандартов 1С (0 токенов в промпте IDE).
- `.agents/` — правила агентов (`1c-protocol.md`) и навыки плагина `origami-platform`.
- `templates/` — шаблоны для downstream-проектов (`AGENTS.template.md`, `origami.config.template.json`, схемы).
- `.bsl-language-server.json` — калиброванные правила линтинга BSL.
