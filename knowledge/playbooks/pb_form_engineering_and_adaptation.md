# Архитектурный паттерн: Инженерия управляемых форм 1С и регламент безопасной доработки в расширениях

> **Статус:** Одобренный корпоративный паттерн Origami Kernel  
> **Область применения:** 1С:Предприятие 8.3 (Интерфейс «Такси», управляемые формы, расширения конфигурации CFE)  
> **Категория:** Пользовательский интерфейс / Управляемые формы / Расширения конфигурации / Стандарты ИТС (Разделы 5898, 3199, 3224, 3226)  

---

## 1. Проблема и критические антипаттерны разработчиков

При разработке и адаптации пользовательских интерфейсов в среде 1С:Предприятие 8.3 разработчики и генеративные AI-агенты регулярно допускают две группы критических ошибок:

### 1.1. Антипаттерн визуального захвата типовых форм в расширениях (Form Lockout Anti-pattern)
* **Суть дефекта:** Разработчик заимствует типовую форму поставщика (ERP, КА, УТ, БП) в расширение конфигурации и редактирует ее визуально в интерактивном редакторе (добавляет кнопки, поля, меняет расположение).
* **Катастрофические последствия:** При обновлении типовой конфигурации поставщика платформа 1С сообщает о критическом конфликте структуры формы. Изменение типового состава реквизитов или дерева элементов в новом релизе типовой конфигурации ломает расширение, блокирует запуск системы и требует ручного слияния форм.
* **Императивное правило Origami:** **В расширениях конфигурации (CFE) категорически запрещено визуальное изменение типовых форм.** Заимствование формы допускается исключительно для подключения программных перехватчиков.

### 1.2. Антипаттерн «пространственной слепоты» Box-Model (Layout Warping)
* **Суть дефекта:** Управляемая форма 1С построена на адаптивной модели контейнеров (Box-Model). Без явного указания ограничений растяжения платформа равномерно распределяет свободное пространство окна между элементами.
* **Последствия:** Многострочные текстовые поля без ограничения высоты растягиваются на весь экран, вытесняя таблицы; командные панели оказываются в произвольных местах; формы расползаются серыми пустотами.

## 2. Канонический регламент доработки форм в расширениях (Extension Safe Injection)

Любая модификация существующей типовой формы в расширении конфигурации выполняется **исключительно программно** на сервере при инициализации формы.

### 2.1. Точка перехвата
Заимствование формы в расширение выполняется только для добавления метода-перехватчика в модуль формы:
1. Используется директива `&После("ПриСозданииНаСервере")` (или `&Перед`, если требуется изменить параметры до типовой инициализации). Использование `&Вместо` запрещено стандартом OPCES-1.1, кроме случаев полного замещения алгоритма.
2. Обработчик обязан делегировать выполнение отдельной изолированной процедуре с префиксом проекта:

```bsl
&После("ПриСозданииНаСервере")
Процедура {{PREFIX}}ПриСозданииНаСервере(Отказ, СтандартнаяОбработка)
	{{PREFIX}}ИнициализироватьЭлементыФормы();
КонецПроцедуры
```

### 2.2. Требования к процедуре модификации интерфейса:
1. **Идемпотентность (Idempotency Guard):**  
   Первой строкой выполняется проверка на существование корневого элемента доработки. Это исключает дублирование элементов при повторной инициализации формы.
2. **Атомарное добавление реквизитов (`ИзменитьРеквизиты`):**  
   Все новые реквизиты формы формируются в массив `РеквизитыДляДобавления` и регистрируются одним вызовом `ИзменитьРеквизиты()`.
3. **Строгая типизация `ОписаниеТипов`:**  
   Запрещено создание нетипизированных реквизитов. Ссылочные типы указываются полностью (`СправочникСсылка.Контрагенты`).
4. **Контейнерная изоляция элементов:**  
   Пользовательские элементы упаковываются в отдельную группу-контейнер (`ВидГруппыФормы.ОбычнаяГруппа`) с аккуратным выделением (`ОтображениеОбычнойГруппы.СлабоеВыделение` или `Нет`), чтобы не нарушать типовую компоновку.
5. **Безопасное позиционирование (`Элементы.Вставить` / `Элементы.Переместить`):**  
   Если требуется разместить элемент перед или после конкретного типового поля, выполняется проверка существования типового элемента (`Если Элементы.Найти("ИмяТиповогоПоля") <> Неопределено`). При отсутствии типового поля в новом релизе конфигурации доработка вставляется в корень формы без аварийного падения.

## 3. Эталонная программная реализация

```bsl
&НаСервере
Процедура {{PREFIX}}ИнициализироватьЭлементыФормы()
	
	// Шаг 1. Защита от повторной инициализации
	ИмяКонтейнера = "{{PREFIX}}ГруппаПользовательскихНастроек";
	Если Элементы.Найти(ИмяКонтейнера) <> Неопределено Тогда
		Возврат;
	КонецЕсли;

	// Шаг 2. Добавление реквизитов формы
	НовыеРеквизиты = Новый Массив;
	НовыеРеквизиты.Добавить(Новый РеквизитФормы(
		"{{PREFIX}}СтатусИнтеграции", 
		Новый ОписаниеТипов("Строка", , Новый КвалификаторыСтроки(50)), 
		, 
		НСтр("ru = 'Статус интеграции'"), 
		Ложь
	));
	НовыеРеквизиты.Добавить(Новый РеквизитФормы(
		"{{PREFIX}}ДатаСинхронизации", 
		Новый ОписаниеТипов("Дата"), 
		, 
		НСтр("ru = 'Дата синхронизации'"), 
		Ложь
	));
	ИзменитьРеквизиты(НовыеРеквизиты);

	// Шаг 3. Определение родительской группы для встраивания
	ГруппаРодитель = Элементы.Найти("ГруппаШапка");
	Если ГруппаРодитель = Неопределено Тогда
		ГруппаРодитель = Элементы;
	КонецЕсли;

	// Шаг 4. Создание визуального контейнера
	ГруппаКонтейнер = Элементы.Добавить(ИмяКонтейнера, Тип("ГруппаФормы"), ГруппаРодитель);
	ГруппаКонтейнер.Вид = ВидГруппыФормы.ОбычнаяГруппа;
	ГруппаКонтейнер.Группировка = ГруппировкаКолонок.ГоризонтальнаяЕслиВозможно;
	ГруппаКонтейнер.ОтображатьЗаголовок = Ложь;
	ГруппаКонтейнер.Отображение = ОтображениеОбычнойГруппы.СлабоеВыделение;

	// Шаг 5. Создание полей ввода
	ПолеСтатус = Элементы.Добавить("{{PREFIX}}ПолеСтатусИнтеграции", Тип("ПолеФормы"), ГруппаКонтейнер);
	ПолеСтатус.Вид = ВидПоляФормы.ПолеНадписи;
	ПолеСтатус.ПутьКДанным = "{{PREFIX}}СтатусИнтеграции";
	ПолеСтатус.Заголовок = НСтр("ru = 'Статус'");

	ПолеДата = Элементы.Добавить("{{PREFIX}}ПолеДатаСинхронизации", Тип("ПолеФормы"), ГруппаКонтейнер);
	ПолеДата.Вид = ВидПоляФормы.ПолеВвода;
	ПолеДата.ПутьКДанным = "{{PREFIX}}ДатаСинхронизации";
	ПолеДата.Заголовок = НСтр("ru = 'Синхронизировано'");
	ПолеДата.ТолькоПросмотр = Истина;

КонецПроцедуры
```

## 4. Восемь инвариантов компоновки интерфейса 1С:ИТС (Такси)

При генерации автономных форм (`Form.xml`) и программных интерфейсов агент обязан соблюдать 8 инвариантов эргономики:

1. **One Stretch Master:** Только один элемент на вертикальном уровне может иметь `VerticalStretch = True` (как правило, табличная часть). Все остальные элементы принудительно получают `VerticalStretch = False`.
2. **Multiline Height Boundary:** Многострочные текстовые поля обязаны иметь фиксированную высоту `Height` (оптимально 3–4 строки) и `VerticalStretch = False`.
3. **Пошаговые мастера (Wizard):** Верхняя командная панель скрыта (`AutoCommandBar.Visible = False`), навигация расположена внизу с привязкой вправо: `[< Назад] [Далее >] [Готово] [Отмена]`.
4. **Симметрия двух колонок:** В двухколоночных макетах ширина заголовков синхронизируется через `AlignLabels = Auto`.
5. **Кластеризация флагов:** 3 и более связанных флажка упаковываются в отдельную группу с заголовком и рамкой `WeakSeparation`.
6. **Обязательность реквизитов:** Обязательные к заполнению реквизиты обязаны иметь `AutoMarkIncomplete = True`.
7. **Компактность отступов:** Для вложенных групп задается `GroupSpacing = Half`.
8. **Детерминизм идентификаторов:** Все `id` элементов генерируются локальным счетчиком без коллизий.

## 5. Чек-лист верификации формы (DoD)

- [ ] В расширении типовая форма не редактировалась через визуальный редактор (чистая структура в расширении).
- [ ] Доработка оформлена строго в `&После("ПриСозданииНаСервере")` с вызовом отдельной процедуры.
- [ ] Все добавляемые реквизиты имеют строгое `ОписаниеТипов`.
- [ ] Реализована проверка `Элементы.Найти(...) <> Неопределено` для предотвращения дублирования.
- [ ] В управляемой форме соблюден принцип One Stretch Master (таблица растягивается, поля шапки фиксированы).
- [ ] Сформирован файл визуального предпросмотра `preview.html` и подтверждено соответствие стилю 1С Такси.
